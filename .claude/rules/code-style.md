# コードスタイルルール

## 基本方針

- シンプルで読みやすいコードを書く
- 過度な抽象化を避ける
- 一つの関数は一つの責務に限定する

## 命名規則

- 変数名・関数名は意味が明確な名前を使用する
- 略語は避け、フルスペルを使用する
- boolean型の変数は `is`, `has`, `can` などの接頭辞をつける

## フォーマット

- インデントはプロジェクトの設定に従う
- 1行の長さは120文字以内を推奨
- 不要な空行を入れない

## コメント

- コードだけで意図が伝わらない場合にのみコメントを書く
- TODO/FIXME コメントには担当者と期限を記載する
- ドキュメントコメントはパブリックAPIにのみ記載する
